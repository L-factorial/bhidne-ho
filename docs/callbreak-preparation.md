# Dealer, shuffle and cut — implemented increment

This guide covers preparation through AWAITING_DISTRIBUTION. The subsequent
dealer-only core StartDistribution command now supports the
[test-console host](test-callbreak-console.md), producing ordered per-card outcomes
in one atomic distribution. Paced per-card transitions remain future work.

## State transitions

| Caller | Command | Before | After / expected actor |
| --- | --- | --- | --- |
| Controller | `PrepareDeal()` | AWAITING_DEAL, DEAL_COMPLETE or AWAITING_REDEAL | AWAITING_SHUFFLE; dealer |
| Dealer | `ShuffleDeck()` | AWAITING_SHUFFLE | SHUFFLING; controller |
| Controller | `CompleteShuffle(deck)` | SHUFFLING | AWAITING_CUT; player after dealer |
| Cutter | `CutDeck(position)` or `SkipCut()` | AWAITING_CUT | AWAITING_DISTRIBUTION; dealer |

SHUFFLING distinguishes the dealer's request from the actual completed shuffle.
The engine contains no randomness or I/O. The trusted host shuffles a standard
deck (live: `SystemRandom`; tests: seeded `Random`) and supplies its exact order.
The engine validates 52 distinct standard cards. Never accept a deck from the
client, and never call completion before the dealer requests shuffling.

Cut positions are integer 1–51; the top pile moves underneath the bottom pile.
Skip preserves order. Only the next player can act, including wraparound from
dealer 4/5 to player 1. Wrong-player, repeated, premature and malformed commands
reject without modifying state or revision.

`MatchState.preparation` contains deal number, attempt, dealer, private deck and
optional cut position. It is separate from DealState: nobody has a hand yet.
Deck order is excluded from public queries and adapter notifications. On a redeal,
PrepareDeal archives the abandoned hands, increments attempt, and preserves the
dealer, deal number and previous scores. Preparing a new scored deal rotates the
dealer as usual.

## Runnable preparation example

```python
from random import SystemRandom
from card_utils import shuffle, standard_52
from callbreak import (
    PrepareDeal, ShuffleDeck, CompleteShuffle, CutDeck,
    GameQuery, Transition, apply_control, apply_player, create_match,
)

state = create_match(initial_dealer=1)
steps = [
    (None, PrepareDeal()),
    (1, ShuffleDeck()),
    (None, CompleteShuffle(shuffle(standard_52(), rng=SystemRandom()))),
    (2, CutDeck(26)),
]
for actor, command in steps:
    result = (apply_control(state, command) if actor is None
              else apply_player(state, actor, command))
    assert isinstance(result, Transition), result
    state = result.state
    print(GameQuery(state).get_turn())
```

At the end, the dealer is the expected actor and START_DISTRIBUTION is the next
action. The preparation-only dispatcher still rejects that command as UNSUPPORTED_COMMAND;
the full dispatch_player adapter maps it to the core StartDistribution command. Legacy controller
StartDeal/Redeal cannot bypass cut/shuffle once PrepareDeal has begun; they reject
in every preparation phase. They remain supported at their original boundaries
for existing simulations and replay records.

## Adapter notifications

`app/adapters/callbreak/preparation.py` provides:

- `control_preparation(state, command, match_id=...)` for trusted PrepareDeal and CompleteShuffle.
- `dispatch_preparation(state, request, match_id=..., player_id=...)` for parsed SHUFFLE_DECK, CUT_DECK and SKIP_CUT.
- `PreparationResult(state, messages)` on success; PlayRejection on domain/context rejection.

The host supplies trusted match/player context and retains the returned state.
Dispatch checks match ID, expected revision and deal attempt; the core checks
the acting player and phase. Parsing errors raise Pydantic ValidationError.
Authentication, roster lookup, command-ID deduplication, concurrency control and
network sending remain host integration work.

| Accepted transition | Adapter output in order |
| --- | --- |
| PrepareDeal | Broadcast DEALER_ASSIGNED; unicast SHUFFLE_REQUESTED to dealer; broadcast TURN_CHANGED |
| ShuffleDeck | Broadcast TURN_CHANGED to SHUFFLING, with no current player |
| CompleteShuffle | Broadcast DECK_SHUFFLED; unicast CUT_REQUESTED to cutter; broadcast TURN_CHANGED |
| CutDeck / SkipCut | Broadcast CUT_COMPLETED; unicast DISTRIBUTION_REQUESTED to dealer; broadcast TURN_CHANGED |

Private prompts are generated by the adapter from core outcomes. Every output
has match/deal/attempt/revision metadata and a sequential adapter event index.
No output includes deck contents. A host delivers only each RoutedEvent.message,
using recipient_player_id for room-scoped routing.

The new commands support private Replay JSON and audit_match. GameQuery reports
preparation phase, expected actor, current deal/attempt and zero cards per player;
previous completed deals remain individually queryable. No cards are playable
until the distribution and bidding stages have happened.

Full gameplay now uses `dispatch_player` and `dispatch_control` in
[`adapter.py`](../app/adapters/callbreak/adapter.py). The preparation-only entry
points remain compatibility wrappers. See [the complete adapter guide](callbreak-adapter-contract.md).
